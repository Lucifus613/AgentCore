Journal connections now explicitly set and verify WAL mode and FULL synchronization before accessing journal data, closing and raising `JournalStoreError` if either setting cannot be confirmed. Retrying an entry ID with the same scope, kind, normalized payload and blob references returns the original stored record, preserving its sequence and timestamp; different content raises `JournalConflictError`. Other integrity errors retain their existing behavior, including repeated blob digests within one entry.
